# Security

## Reporting a vulnerability

Report privately, not in a public issue.

- GitHub Security Advisories: **Security → Report a vulnerability** on this
  repository.
- Or e-mail the maintainer listed in the repository settings, with
  `[peek-security]` in the subject.

Please include the version (`peek version`), what you did, what happened, and
what you expected. A proof of concept helps. If you need encrypted transport,
say so and a key will be sent back.

**Expected response:** acknowledgement within 3 working days, an assessment
within 10 days, and a fix released as soon as it is ready — critical issues
first. We will credit you unless you prefer otherwise, and we ask that you give
us a reasonable window before publishing.

Out of scope: anything requiring physical access to the server, attacks on a
deliberately misconfigured instance (creation open to the internet, no TLS),
denial of service by raw volume, and reports generated by a scanner without a
demonstrated impact.

## What Peek guarantees

A secret is encrypted in the sender's browser with AES-256-GCM. The key is
generated there, lives in the URL fragment — which browsers never transmit —
and never reaches the server. There is no key escrow, no recovery path and no
administrator override.

The server stores a ciphertext, `SHA-256(read token)`, `SHA-256(receipt
token)`, the KDF parameters and the limits. It releases a ciphertext only after
a constant-time check of the read token, and spends a read only once, inside a
transaction. A wrong passphrase, and a link-preview bot, cost nothing.

[docs/CRYPTO.md](docs/CRYPTO.md) is the normative description.
[docs/THREAT-MODEL.md](docs/THREAT-MODEL.md) states plainly what this does
**not** protect against — chiefly a compromised server serving modified
JavaScript, and anyone who has the link.

## Hardening in the product

- **Transport and headers**: CSP with no third-party origin, no
  `'unsafe-inline'` and no `'unsafe-eval'` (`'wasm-unsafe-eval'` is present for
  the Argon2id WebAssembly module, and permits WebAssembly only),
  `Referrer-Policy: no-referrer`, `X-Content-Type-Options`,
  `frame-ancestors 'none'`, COOP, CORP, `Permissions-Policy`, optional HSTS.
- **Caching**: `no-store` on everything that touches a secret, including the
  application shell.
- **Indexing**: `noindex` and a `robots.txt` that disallows everything.
- **Network**: two listeners so recipient pages can be published alone, CIDR
  gates answering 404, forwarded headers honoured only from declared proxies,
  optional PROXY protocol.
- **Abuse**: token buckets per real client IP on creation, reads, login and the
  API; bounded passphrase attempts that destroy the secret on exhaustion.
- **Logging**: no secret, key, passphrase, fragment or request body is ever
  logged; the access log records the route pattern, not the URL; IP
  anonymisation and audit retention are configurable.
- **Process**: hardened systemd unit (`ProtectSystem=strict`, `NoNewPrivileges`,
  `MemoryDenyWriteExecute`, `SystemCallFilter=@system-service`, no
  capabilities), dedicated account with no shell, `0400` master key.
- **Supply chain**: releases are signed with minisign and the public key is
  compiled into the binary, so `peek update` verifies the next release without
  trusting a web server. Checksums and an SBOM ship with every release, and CI
  runs `govulncheck` and `npm audit`.
- **Air-gapped by default**: no CDN, no web font, no analytics, no telemetry.
  Outbound traffic only for SMTP, an IdP, webhooks and the update check — each
  configured by you, each disableable.

## Supported versions

While the product is pre-1.0, security fixes go to the latest release. Once
1.0.0 ships, the current minor and the one before it are supported.

## Hardening a deployment

1. Publish `public_listen` only; keep `internal_listen` on the LAN.
2. Set `trusted_proxies` to your load balancer addresses, nothing wider.
3. Set `admin_allowed_cidrs` and `create_allowed_cidrs`.
4. Terminate TLS properly and send HSTS from exactly one place.
5. Set `backup.passphrase` and keep `backup.keep` small.
6. Copy `master.key` somewhere safe, away from the database backups.
7. Run `peek doctor --external` after every change to the exposure.
8. Watch `request.admin_blocked` and `secret.bad_passphrase` in the audit
   trail; export it to your SIEM when that lands in M5.
